Getting started

Agent Plugins adds skills and connectors to the AI apps on your PC: GitHub Copilot, Cursor, and Claude, and also OpenCode, pi, Codex, and Grok Build. You pick them here; the app puts them in place and keeps them up to date.

Two words

A skill teaches an assistant one job, such as turning rough notes into a standup update. The assistant uses it on its own when your request matches, or only when you ask for it by name, depending on the skill.

A connector (an MCP server) lets the assistant use a tool: look something up, open a ticket, read a database. Some run a small program on your PC, others connect to an online service. Before one is added, the app shows you what it runs or where it connects, and asks.

Install your first skill

  1. Get the app

    Download Agent Plugins, run the installer, and open it once. It stays in the tray (near the clock) and starts with Windows, so skills stay up to date and anything removed from the marketplace is removed from your PC too.

  2. Pick a skill

    Browse skills, open one, and check Works in for your apps. Then choose Install in Agent Plugins. Your browser asks Open Agent Plugins?: tick Always allow and choose Open.

  3. Say yes in the app

    The app lists what it adds and to which apps, and waits for you. A connector also shows what it runs; approve it only if you trust whoever published it.

Where it shows up

The assistant knows a skill by its space and name, like jane-meeting-notes. Start a new chat after installing; most apps read skills when a chat starts.

App Skills Connectors
GitHub Copilot Ask in Copilot Chat's agent mode; it picks the skill when your request matches. Listed under the chat's tools button. In VS Code, reload the window if one is missing.
Cursor Type / in the Agent chat to see them, or just ask. Settings, then MCP.
Claude Code Type / and the skill's name, or just ask. Type /mcp in a new session.
Claude Desktop Not from here: Claude Desktop takes skills from your claude.ai account, under Customize > Skills. Quit it from the tray and open it again, then look in the tools menu. It only runs connectors on your PC, not online ones.
OpenCode, Codex, Grok Build Start a new session and ask, or name the skill. Start a new session.
pi Type /skill: and the skill's name, or just ask. pi doesn't use connectors.

If something doesn't work

  • Nothing happens when you choose Install. The app isn't installed, or hasn't been opened since it was. Open Agent Plugins once, then try again.
  • The browser never asked to open the app. You may have chosen "don't allow" before. Open the app yourself and search for the skill there.
  • The assistant doesn't use the skill. Start a new chat. If the skill only runs when you ask, name it in your request.
  • A connector installs but doesn't work. Some need a key or another program such as Node.js. The app tells you what's missing; if it doesn't, use Tell the owners on the skill's page.
  • The app's status button is red. Select it: each problem says what to do.
  • The app asks to be updated. Download the new version and run it; your skills stay.

Still stuck? Use Report a problem on the skill's page. Its owners and the marketplace admins see it.

Source manifest

The source manifest is a file named agent-plugins.json at the root of a source archive. Agent Plugins reads that file to learn the source identity and the packages it can install. Publish the tree as a zip, tar, or tar.gz at a raw HTTPS URL. A source repository is a separate catalog that lists those archives.

Create a compatible source

  1. Make the source tree

    Put agent-plugins.json at the top level. Host a zip, tar, or tar.gz of that tree at an https:// artifact URL. Artifact URLs may include a query string and must not include credentials. 

    example-source/
├── agent-plugins.json
├── mcp/
│   └── database.json
└── skills/
    └── review/
        └── SKILL.md

  2. Write the manifest

    Set version to 2. Give the source a stable id. Add one package for each installable unit. A package lists one or more skill or mcpServer components. 

    {
  "version": 2,
  "source": {
    "id": "example",
    "name": "Example source",
    "description": "Portable review configuration."
  },
  "packages": [
    {
      "id": "review",
      "components": [
        { "kind": "skill", "id": "review", "path": "skills/review" },
        { "kind": "mcpServer", "id": "database", "path": "mcp/database.json" }
      ]
    }
  ]
}
    Field Rule
    version Required integer. Must be 2.
    source.id 2–16 lowercase letters, digits, or single hyphens. Must begin with a letter. Namespaces package and install names.
    source.name Required display name, 1–120 characters.
    source.description Required description, 1–1,024 characters.
    packages[].id 1–64 lowercase letters, digits, or single hyphens. Unique inside the source.
    packages[].components[].kind skill or mcpServer.
    packages[].components[].id Required when the package has several components. A single component may inherit the package id.
    packages[].components[].path Archive-relative skill directory or MCP document.

    Unknown fields are rejected. Package ids must be unique. Generic file destinations, always-on instruction files, and native agent-plugin@1.0.0 package trees are not accepted.

  3. Write the skill

    A skill path is a directory that contains SKILL.md. The frontmatter name must match the component id. The directory name does not have to match. Agent Plugins rewrites only name to source-id-component-id on install; other keys and the Markdown body are copied through. 

    ---
name: review
description: Reviews a change before it is submitted.
disable-model-invocation: true
---

# Review

Follow the repository's review workflow.
    Field Rule
    name Required. 1–64 lowercase letters, digits, or single hyphens. Must equal the component id.
    description Required non-empty string, at most 1,024 characters.
    disable-model-invocation Optional boolean.

  4. Write the MCP document

    An mcpServer path is a JSON file. Set $schema to the Agent Plugins 1.0.0 MCP schema and declare one or more servers. A stdio command must be a bare executable on PATH. 

    {
  "$schema": "https://agent-plugins.org/schemas/1.0.0/mcp.schema.json",
  "mcpServers": {
    "database": {
      "type": "stdio",
      "command": "npx",
      "args": ["@acme/database-mcp"]
    }
  }
}
    Field Rule
    $schema Required. Must be https://agent-plugins.org/schemas/1.0.0/mcp.schema.json.
    mcpServers Required object with at least one entry. Keys are 1–64 character server names.
    type stdio, streamable-http, or sse.
    command Required for stdio. Bare executable name. No ./bin/server or ${PLUGIN_ROOT}.
    url Required for remote types. https, or http only on localhost.
    sensitive headers Authorization and API-key headers must be ${ENV_NAME}, not a literal secret.

  5. Check paths and limits

    • Directories are copied recursively. Executable permission bits are preserved where supported.
    • Symlinks, special files, globs, commands, hooks, and environment-variable expansion are not supported.
    • The manifest is limited to 1 MB. Selected content is limited to 2,000 files and 50 MB.

  6. Validate and publish

    Check the JSON before committing it:

    jq empty agent-plugins.json

    For structural validation, save the v2 JSON Schema beside the manifest and run:

    npx ajv-cli validate --spec=draft2020 --strict=false \
  -s source-manifest.schema.json \
  -d agent-plugins.json

    Upload an archive of the tree with every referenced path. List that HTTPS URL in a source repository. In Agent Plugins, add the listed source from Manage Sources. Adding a source validates the tree and makes packages available; it does not install them.

Source repository

A source repository is a catalog that lists sources. It is not installable. Packages appear only after a listed source is added. Publish the document as raw JSON at an HTTPS URL. The conventional filename is agent-plugins-repository.json.

Create a compatible catalog

  1. Write the catalog

    Set version to 1. Give the catalog a stable id, then list each source by name, description, and HTTPS archive URL.

    {
  "version": 1,
  "repository": {
    "id": "acme",
    "name": "Acme sources",
    "description": "Official portable sources."
  },
  "sources": [
    {
      "name": "Review workflows",
      "description": "Review skill and database MCP server.",
      "url": "https://nexus.example.com/repository/raw/sources/review-latest.zip"
    }
  ]
}
    Field Rule
    version Required integer. Must be 1.
    repository.id 2–32 lowercase letters, digits, or single hyphens. Must begin with a letter.
    repository.name Required display name, 1–120 characters.
    repository.description Required description, 1–1,024 characters.
    sources[].url HTTPS archive URL. No credentials. Query strings are kept.

    Unknown fields are rejected. Duplicate URLs after canonicalization are rejected. At most 200 listed sources. Nested catalogs are not accepted.

  2. Validate and publish

    Check the JSON before publishing it:

    jq empty agent-plugins-repository.json

    For structural validation, save the catalog JSON Schema beside the document and run:

    npx ajv-cli validate --spec=draft2020 --strict=false \
  -s source-repository.schema.json \
  -d agent-plugins-repository.json

    Host the JSON at a stable HTTPS URL. In Agent Plugins, listed sources appear in Manage Sources by name and description. Select Add on a listed source. Adding a source does not install its packages.

Publishing from the command line

Everything the portal does, the agent-plugins command does too, signed in as you. Use it from a terminal, a script, or a coding agent. If agent-plugins is not found, run it by its full path, "%LOCALAPPDATA%\Agent Plugins\agent-plugins.com", or add that folder to your user PATH.

  1. Check who you publish as

    agent-plugins whoami

    publishes to lists every space you may publish to: your own, the teams you are on, and official if you are an approved publisher.

  2. Publish

    Point publish at what you have. It is wrapped into one package, checked for credentials, validated, and uploaded.

    You have Command
    One skill (a folder with SKILL.md) agent-plugins publish ./meeting-notes --version 1.0.0
    A skill pack (a folder of skill folders) agent-plugins publish ./writing-helpers --version 1.0.0
    An MCP server (one mcp.json-shaped file) agent-plugins publish ./database.json --version 1.0.0
    A source tree with agent-plugins.json agent-plugins publish ./source --version 1.0.0

    Add --namespace data-team to publish to a team, --private to keep it to yourself and the people you share it with, --package-id to choose the ID, --tags a,b, --changelog "…", and --yes to skip the confirmation.

  3. Who checks it

    A version goes live when you publish it. The one exception is an MCP server that everyone can see: an admin checks the package once before it shows for everyone. You, your team, and people you share it with can use it right away.

    Publishing to a skill you don't own sends your files to its owners as a suggestion, with --message "…" saying what you changed. Owners answer suggestions on My skills or with agent-plugins review.

  4. Choose who can see it

    agent-plugins share jacob/review --private --add CORP\jane --add team:platform
agent-plugins share jacob/review --link
agent-plugins share jacob/review --public

    A skill follows its space unless you set it. Private means you (or your team) and the people and teams you add. Anyone who opens the share link is added to the list. Use --inherit to follow the space again.

  5. Work as a team

    agent-plugins team create data-team --name "Data Team"
agent-plugins team invite data-team
agent-plugins team add data-team CORP\jane

    Anyone can start a team. Everyone on it can publish to its space; owners add and remove people. Send the invite link to let colleagues join themselves.

  6. Bundle skills

    agent-plugins bundle set data-team/starter --name "Starter kit" jacob/review data-team/sql

    A bundle groups skills that already exist, anyone's, so people can install them all at once. Each one still installs on its own.

  7. Install

    On this site, choose Install in Agent Plugins: the app opens and asks before it adds anything. From a terminal:

    agent-plugins search meeting
agent-plugins install jacob/meeting-notes
agent-plugins install data-team/starter
agent-plugins install data-team/writing-helpers/tone

    The last line installs one skill of a pack. Installing an MCP server needs --approve-mcp, after you have read what it runs.

  8. Take it back

    agent-plugins revoke jacob/review

    This removes it from every PC at their next check, and nobody can install it until you run it again with --undo.
