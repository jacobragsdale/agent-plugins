# App reference

What the Agent Plugins window shows, where it writes, and what it does on its own. For the checks behind **System status** see [the preflight reference](preflight-reference.md); for the terminal equivalents see [the CLI reference](cli-reference.md).

### Opening an app with a message

**Create a skill** and the skill tutorial's **Show me** open an AI app with a message, on Windows, macOS, and Linux. A dialog asks which app first, even when there is only one, with the first one chosen. It lists each app below whose AI app is detected and whose program is found, in this order. **Open** opens it; the window then says what to do next. Nothing is closed: each app picks up a new skill without a restart.

| App                                                           | How it opens                                                                                                                                                   |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| GitHub Copilot in VS Code, GitHub Copilot in VS Code Insiders | A new window sends the message to GitHub Copilot.                                                                                                              |
| GitHub Copilot CLI, Claude Code                               | A new terminal window runs it; the message is sent once you trust the folder.                                                                                  |
| Cursor                                                        | Cursor asks to create a chat with the message: choose **Create Chat**, then send it. Cursor drops the message if it is not signed in; sign in, then try again. |
| Claude Desktop                                                | A new Code tab session opens with the message typed; press Enter.                                                                                              |
| OpenCode, pi, Grok Build                                      | A new terminal window runs it, and the message is sent.                                                                                                        |
| Codex CLI                                                     | A new terminal window runs it; the message is sent after its trust screen.                                                                                     |
| ChatGPT (Codex)                                               | A new Codex thread opens with the message typed; press Enter. Not offered on Linux.                                                                            |

Terminal windows start in your home folder. Windows opens a new console window, macOS opens Terminal, and Linux uses `$TERMINAL`, then `x-terminal-emulator`, then the first common terminal it finds.

An app is looked for in the same places detection searches, so an app shown as detected is one that can be opened: on Windows, the running copy, uninstall entries, App Paths, registered link handlers, MSIX app aliases, default install folders, Scoop, and PATH; on macOS, the app by its bundle id and command-line tools on your login shell's PATH; on Linux, default install folders and PATH.

## Connectors

A connector is an MCP server: a program an AI app starts on this computer, or an online service it sends requests to.

### Allow connector

**Allow connector?** opens before a package or bundle installs a connector that is new to this computer, or changed since you allowed it. It says `A connector is a program on this computer or an online service that your AI apps use. Allow it only if you trust who published it.`, then for each package:

- its name, with **Checked by IT** when an admin let everyone see its MCP server, or **Not checked by IT** when you see it through a team, a share, or your own space without that approval, and `From <publisher>`;
- for each connector: its installed name, `(changed in this update)` when it is installed and this version changes it, `Starts a program called <command> on this computer.` or `Sends your requests to <host>.`, `Goes to <apps>.` or `None of the AI apps on this computer can use it.`, the missing-program line from [Card notes](#card-notes) when it applies, and the exact command line or address.

**Settings it needs** lists every environment variable the connectors read, missing ones first, each with a password field. A missing one reads `<NAME> isn't set yet. Paste the value from the publisher's instructions, or add it later.`; one already set reads `<NAME> is already set. Type a new value only to change it.`

**Allow and install** saves any values you typed (see [Connector settings](#connector-settings)), then installs. **Cancel** writes nothing.

### Connector settings

**Connector settings** is the same dialog without the install: fill in or change the values installed connectors read. Each value is saved for your Windows account in `HKCU\Environment`, the way **Edit environment variables for your account** saves it, and in the app's own process; the app then tells Windows the environment changed. On macOS it uses `launchctl setenv`. Other platforms refuse and ask you to set the variable in your shell profile. Quit and reopen your AI apps so they read the new value.

A name must be uppercase letters, digits, and underscores, at most 128 characters; `PATH`, `HOME`, `USERPROFILE`, and `APPDATA` are refused. A value must be 1–8,192 characters. Values are not written to the ledger, the log, or the marketplace.

### Which apps use a connector

**Which apps use it?** lists the detected apps that can take the connector, ticked where it goes now. Clearing an app removes the connector from that app's configuration and keeps it out on later updates; the component row then reads `Kept out of N app(s).` Ticking an app back installs it there, after **Allow connector?**. At least one app must stay ticked; to remove it everywhere, uninstall it. The choice is kept in `package-choices.json`.

## System status

**System status** leads with Windows sign-in, the marketplace server, and the agents on this computer, then collapsed **Agent details** and **All checks**. **Run diagnostics** re-runs every check. See [the preflight reference](preflight-reference.md).

**Advanced** holds:

| Button              | Effect                                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------------------------------- |
| **Manage sources…** | Lists the catalog's sources with **Add** or **Remove**, plus any added source the catalog no longer lists. |
| **Open log**        | Shows the [log file](#state-on-disk) in its folder.                                                        |
| **Reset…**          | Confirms, then uninstalls every package and deletes Agent Plugins' config, cache, and data.                |

### Download page

**Update Agent Plugins** (from a failed or warning `server.clientVersion` check) and **Get it** open the `DownloadUrl` policy's address when IT set one, otherwise `<marketplace>/#download`. See [the rollout guide](rollout-guide.md#point-it-at-your-marketplace).

## Automatic retries

| Failure                                                                                 | What happens                                                                                                                                                                                          |
| --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| An action fails on a locked file or a dropped connection (kind `locked` or `retryable`) | The window shows **Trying again…**, waits 3 seconds, and runs the action once more. If that fails too, the error adds `Close <app> and try again.` when it names an AI app, otherwise a generic hint. |
| An action or sync fails because no server answered (kind `offline`)                     | No red error. The offline notice appears, and the next sync retries.                                                                                                                                  |
| A marketplace or archive request fails to connect, times out, or answers 5xx or 429     | Retried twice, after 1 then 2 seconds, or after the server's `Retry-After` up to 10 seconds.                                                                                                          |
| A file rename, delete, copy, or write hits a transient Windows sharing or access error  | Retried for up to 4 seconds before it counts as locked.                                                                                                                                               |

The error kinds are listed in [the codebase map](codebase-map.md#ipc-errors).

## Tray

| Menu item                 | Effect                                                                     |
| ------------------------- | -------------------------------------------------------------------------- |
| **Open Agent Plugins**    | Shows the window.                                                          |
| **Check for Updates Now** | Opens the window and runs a sync, so the check and its result show there.  |
| **Launch at Login**       | Toggles autostart. The app then starts with `--background`, window hidden. |
| **Quit Agent Plugins**    | Exits. Scheduled syncs stop until it runs again.                           |

Launch at Login starts on: a release build turns it on the first time it runs, and after that follows the menu. The `LaunchAtLogin` policy (`REG_DWORD` under `HKLM` or `HKCU\Software\Policies\AgentPlugins`) turns it on (`1`) or off (`0`) at every start instead. Removals and updates reach this computer only while the app runs.

Closing the window hides it; the app keeps running in the tray. The first time, a desktop notification says `Agent Plugins is still running in the system tray, so your skills stay up to date. Quit it from the tray icon.`

### Desktop notifications

After a sync, while the window is not focused, Agent Plugins shows a desktop notification titled **Agent Plugins** for each of these, at most three, then `And N more. Open Agent Plugins to see them.`:

- `<name> was removed from this computer by its publisher or IT.`
- `<name> was updated to version <version>.`
- each marketplace notification since the last sync, in the marketplace's words.

## Links

A marketplace page's **Install in Agent Plugins** button opens an `agent-plugins://` link. The browser may first ask to open Agent Plugins; allow it. The app comes forward (it starts if it wasn't running) and handles the link in its own window: a web page can open these links, so nothing changes until you confirm here.

| Link                                              | What the window does                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `agent-plugins://install/<namespace>/<id>`        | Checks for updates first if the package or bundle isn't listed yet, then asks **Install <name>?**, naming the publisher and version, what it adds, and the apps here that will get it. When none of them can take it, the dialog says `<name> can't be added here` with the reason and offers **Show it**. **Install** takes the same path as the card's button, so a connector still asks **Allow connector?**. For a bundle it lists the members and offers **Install all** or **Install the rest**. |
| `agent-plugins://install/<namespace>/<id>/<part>` | The same, for one skill or connector of a package.                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `agent-plugins://open/<namespace>/<id>`           | Clears the search and scrolls to the card, which is outlined for a moment.                                                                                                                                                                                                                                                                                                                                                                                                                             |

A link never uninstalls or restores anything. When the package is already installed (or changed on this computer), the window says so and offers **Show it**. When it still isn't listed after the check, the notice reads `That isn't available to you. Ask whoever sent it to check that it's shared with you.` One confirmation shows at a time; a newer link replaces one still waiting.

**Open a link** takes a link pasted from a message: a team invite (`https://<marketplace>/l/<code>`) or a share link, or just its code. **Check** says what it is: `<name> invited you to join <team>.` with **Join**, or `<name> shared <package> with you.` with **Get it**. Joining refreshes the window, so the team's skills and its publish space appear. Getting a shared package or bundle opens the same install confirmation a link does; a shared space is scrolled to.

## Teams, sharing, and bundles

These need the marketplace; they appear once the window knows who you are.

### Teams

**Teams** lists the teams you are in with your role, whether its skills are private, and its size. **Open** shows a team; **Create a team** and **Open a link** start the other two flows.

| In a team                                    | Who                        | Effect                                                                                                                                                              |
| -------------------------------------------- | -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Members list                                 | Everyone                   | Each member's name and account; owners are marked **Owner**.                                                                                                        |
| **Add people**                               | Owners                     | Searches people who have used the marketplace as you type. A full account typed in (`CORP\jane`, `jane@corp.example`) can be added even if it hasn't been seen yet. |
| **Make owner** / **Make member**, **Remove** | Owners                     | Changes a member's role, or takes them out of the team. The last owner can't be removed.                                                                            |
| **Copy invite link**                         | Everyone                   | Creates the invite link if there isn't one and copies it. Anyone at the company who opens it can join and publish there.                                            |
| **Reset**                                    | Owners                     | Replaces the invite link; the old one stops working.                                                                                                                |
| **Who can see its skills…**                  | Everyone; owners change it | Opens [Share](#share) for the team's space.                                                                                                                         |
| **Rename**                                   | Owners                     | Changes the team's name. Its short name (the namespace) never changes, because installed skill names start with it.                                                 |
| **Leave team**                               | Members                    | Takes you out of the team.                                                                                                                                          |
| **Delete team**                              | Owners                     | Deletes a team that has no skills or bundles.                                                                                                                       |

**Create a team** asks for the team's name, suggests a short name from it (2–16 lowercase letters, numbers, or hyphens, starting with a letter), and asks who can see the team's skills: **Only team members, and people you share with** (the default) or **Everyone at the company**. You become its owner.

### Share

**Share…** on a source, package, or bundle you own, or **Who can see its skills…** on a team, opens **Share “<name>”**:

- **General access**: **Same as its space** (packages and bundles only), **Private** (only the space's owners and the list), or **Everyone at the company**.
- **People and teams**: the list of who may see it while it's private, with **Remove** on each. **Add a person or team…** searches as you type. Windows groups already on the list are shown and can be removed. The list is kept when general access changes.
- **Share link**: **Copy link** creates the link if needed and copies it; anyone at the company who opens it can install it and is added to the list. **Reset** replaces it.

**Save** applies the setting and refreshes the window. Sharing never lets anyone change what you publish; publishing takes team membership.

### Bundles

A bundle is a set of existing packages people install together. Every member is still an ordinary package in its own source, with its own card and button.

The **Bundles** group, above the sources, shows each bundle you can see with its publisher, its size, and how many of its members are installed. Its button is **Install all** when none are, **Install the rest** when some are, and **Uninstall all** when all are. **Show its skills** lists the members as cards; members you can't see are counted instead. On a bundle you own, **Share…**, **Edit**, and **Delete** are beside the button.

**New bundle** and **Edit** open the bundle editor: a name, what it's for, whose bundle it is (**My space**, or one of your teams; fixed once created), and a searchable list of marketplace packages to tick, at most 50.

## Package states

The badge on a card, and the button beside it.

| State                | Badge                    | Button              | Meaning                                                                                                                                                                                                                                                          |
| -------------------- | ------------------------ | ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `available`          | none                     | Install             | Not installed.                                                                                                                                                                                                                                                   |
| `installed`          | none                     | Uninstall           | Installed, and every owned file still matches the ledger.                                                                                                                                                                                                        |
| `updateAvailable`    | Update available         | Update              | The source publishes a different digest for this package.                                                                                                                                                                                                        |
| `partiallyInstalled` | Partly installed         | Update              | Some components are installed; others are not, or an owned resource no longer matches the plan.                                                                                                                                                                  |
| `missing`            | Restoring on next check  | Uninstall           | Files of the installed version are gone and none of the rest changed. The next sync re-creates them from the saved copy. Uninstalling succeeds with nothing left to remove.                                                                                      |
| `modified`           | Changed on this computer | Restore original…   | An owned file was edited outside Agent Plugins. Updates skip it. **Restore original…** confirms, backs up the changed copy, and reinstalls the published content. **More** also offers **Keep my version…** and **Remove…**.                                     |
| `removed`            | No longer offered        | Uninstall           | Installed, but the source no longer publishes it, or you may no longer see it.                                                                                                                                                                                   |
| `sourceConflict`     | From another source      | From another source | Another source already owns this package ID. Disabled.                                                                                                                                                                                                           |
| `conflict`           | Files already there      | Replace…            | Not installed, and a folder or settings entry Agent Plugins did not install is where it goes, with different content. **Replace…** confirms, backs it up, then installs. A folder that already holds exactly the published content is taken over without asking. |

When an owned file cannot be read, the package keeps the state it last had instead of changing to one of these.

Component rows carry the same states, and a kind badge: **Skill**, or **Connector** for an MCP server. Every package with a skill, and every skill row, shows **Only when you ask** or **Used automatically**. It starts from the skill's `disable-model-invocation`, and clicking it flips the setting and reinstalls the installed skills with it, so their `SKILL.md` carries the new value. The choice is kept in `invocation-overrides.json` in the app's data folder and survives updates. On the package card, clicking sets every skill in the package; the card reads **Only when you ask** only when every skill is. A package published to the official lane shows **Official**, one from a team namespace shows **Team**, one that is private shows **Private**, and one you see only because someone shared it with you shows **Shared with you**.

An update applies only the components already installed on that package. Installing a component you skipped the first time is a separate action.

### Source badges

| Badge                    | Meaning                                                                                                                                                                                       |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Saved copy from <time>` | The last sync could not refresh this source or catalog; its packages are the copy saved at `<time>`. Grey, never red: the next sync retries on its own. The badge's tooltip gives the reason. |

A skill directory is named `<sourceId>-<skillName>`. Every target except Claude Code shares one copy under `~/.agents/skills`; the ledger records each target as a consumer, and the directory is deleted only when the last one goes away. Each app's MCP entry is written in that app's own spelling; [the adapter contract](adapter-contract.md#mcp-spelling) lists them. Configuration files are edited in place through their syntax tree: the package's entry is added, replaced, or removed, and every other key keeps its order, formatting, and comments.

A JSON or JSONC configuration file that starts with a UTF-8 byte order mark, or is empty, is read as settings. One that cannot be parsed, or that its app holds open on Windows, skips that app only: the rest of the package installs, and the action result names the app and the file. A sync retries the skipped app while Agent Plugins stays open.

Replacing an unmanaged destination, restoring an original, or force-removing modified content first copies the existing content to `~/.agents/.agent-plugins-backups`. The action result names the backup path and offers **Open folder**.

## Background behavior

- **Detection.** Every installed agent is configured. A version probe (`<command> --version`) that runs past 3 seconds or errors keeps the agent as it was, and **System status** says `couldn't check just now` instead of `not installed`. Results are cached for 60 seconds; a sync, an on-demand diagnostics run, or focusing the window clears that cache.
- **Window focus.** Bringing the window forward looks for agents again, at most once a minute; the first focus only starts that clock. It then syncs when the set of agents changed, or when no sync is running and the last one finished over a minute ago.
- **Sync schedule.** 15 minutes after a sync that reached every server. After a sync that failed or reached only some servers, the next one comes 1, 2, then 5 minutes later, then every 15 minutes again. Syncs you start count toward this. A sync also runs right after the computer wakes from sleep, and on **Refresh** or **Check for Updates Now**.
- **Sync.** Fetches every catalog and source a few at a time, skipping a marketplace source whose catalog `digest` equals the ETag of the copy already saved, and asking for the marketplace index with its saved ETag, with a 10-second connect timeout and a 120-second download timeout; after one connection to a host fails, the rest of that pass skips the host. It then activates what arrived, subscribes to any catalog source not yet added, repairs and updates installed packages, runs preflight, and posts a `heartbeat` event. Installs and removals are not held up while it downloads.
- **Repairs.** Missing files of installed packages are re-created from the saved copy of the installed version. A connector entry comes back only when the ledger still holds the exact entry you approved. Installed skills are added to agents detected since, and released from agents no longer detected and from apps you kept a connector out of. A connector is added to another agent again only for a package that skipped that agent. Backups under `~/.agents/.agent-plugins-backups` older than 30 days are deleted.
- **Updates.** Installed packages whose state is `updateAvailable` are updated during sync, except held ones and ones whose MCP entries are new or changed (see [Approvals](#approvals-and-confirmations)). Nothing is updated while no agent is detected.
- **Notifications.** After a sync that reached the marketplace, the app reads marketplace notifications newer than the last one it saw. The first time it only records where they stand, so there is no backlog. New ones join the background report and, while the window is not focused, [desktop notifications](#desktop-notifications).
- **Pulled packages.** When the marketplace lists a package as pulled from every PC (revoked by its publisher or an admin), the sync uninstalls it, backing up any copy you changed first, and the background report names it.
- **Offline.** A failed refresh keeps the last validated snapshot and marks the source **Saved copy**. A failed catalog fetch does not stop source refresh. **Last checked** does not move while every server is unreachable or answers with something unusable, such as a Wi-Fi sign-in page; such a pass counts as failed for the sync schedule.
- **Gone sources.** A source or catalog whose archive answers 404 or 410 (unpublished, or no longer visible to you) keeps its saved copy for what is installed from it, but installs nothing new from it, and its **Saved copy** badge's tooltip says `<name> was not found on the server (first noticed <date>).` After 3 such answers spanning at least 3 days, with no successful fetch in between, it is retired: its cache is deleted, and it is dropped from the configuration once nothing from it is installed. A retired source's installed packages show **No longer offered** until you uninstall them. The default catalog is never retired.
- **Events.** `install`, `update`, `uninstall`, and `heartbeat` are posted; a heartbeat also carries this computer's name and the marketplace version of each installed package: the version it holds, including an older one whose updates you hold (known once a sync has seen it installed as the current version). They are posted to the marketplace from a background thread. Events that cannot be delivered wait in an outbox and go out, oldest first, with the next report. The outbox keeps the newest 1,000 events from the last 7 days and only the newest heartbeat. Reporting never blocks or fails an operation.

Each of `sources.json`, `agent-profiles.json`, and `installations.json` keeps a `.previous` copy, the last good version. When a file cannot be parsed:

| File                        | Recovery                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `installations.json`        | Moved aside to `installations.json.corrupt-<timestamp>` and replaced by `.previous`, or started empty when that is damaged too. The next sync then forgets a package uninstalled since, and takes one updated since as installed at the new version when its files match it exactly. A single unreadable record is dropped and the rest kept. A ledger written by a newer version is shown but never changed; every change fails until Agent Plugins is updated. |
| `sources.json`              | Replaced by `.previous`, or rebuilt from the saved default catalog and the sources of installed packages. The damaged file is kept as `sources.json.corrupt-<timestamp>`. A file from a newer version is left alone and reported as an error.                                                                                                                                                                                                                    |
| `agent-profiles.json`       | Replaced by `.previous`, or started empty. Detection fills it again.                                                                                                                                                                                                                                                                                                                                                                                             |
| `package-choices.json`      | Moved aside to `package-choices.json.corrupt-<timestamp>` and replaced by `.previous` (the choices before the last change), or started empty when that is missing or damaged too.                                                                                                                                                                                                                                                                                |
| `resource-transaction.json` | Moved aside to `resource-transaction.json.corrupt-<timestamp>`.                                                                                                                                                                                                                                                                                                                                                                                                  |

Recovery of an interrupted transaction runs before every ledger read and change, not only at launch: a journal whose transaction is absent from the ledger is rolled back, and one already committed is cleaned up. A rollback that cannot finish keeps the journal, refuses new changes with `An earlier change is still being undone`, and is retried on the next sync. Staging files older than 10 minutes that an interrupted run left behind are removed during sync.
